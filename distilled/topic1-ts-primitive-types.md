# 1.1 原始类型 & 字面量类型

**它解决什么问题**
JS 的变量「什么都能装」，拼错字符串、传错类型都得运行时才炸；TS 用类型注解把错误前移到编译期。

**核心机制**
- 用 `变量: 类型` 给值贴标签，原始类型与 JS 的 7 种一一对应
- 类型推断省去手写注解：`let` 拓宽为宽类型，`const` 保留字面量类型
- 字面量联合（`'a' | 'b'`）把散落字符串收成有限取值集
- 把对象字段标成字面量联合，比较运算两端才真正类型安全

**最容易被追问的点**
- "`let s = 'open'` 推断成什么？" -> `string`，不是 `'open'`；let 会把字面量拓宽为宽类型
- "拓宽有什么坏处？" -> 保护失效，`s = 'shiped'` 拼错也静默通过，错误退回运行时
- "`const s = 'open'` 为什么安全？" -> const 推断成字面量 `'open'`，赋别的值编译报错
- "怎么让 let 也精确？" -> 显式注解 `let s: Status = 'open'`

**一句话类比**
原始类型像不限量自助餐券（任何 string 都行），字面量联合像套餐菜单（只能从几道菜选），点错菜当场被拦。
