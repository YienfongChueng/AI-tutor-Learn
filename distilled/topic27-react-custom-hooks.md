# 2.7 自定义 Hook 实战

**它解决什么问题**
同一套"状态 + 操作 + 副作用"在多个组件里复制粘贴；组件想复用的是逻辑而不是 UI，自定义 Hook 把"创建和管理状态的代码"搬出去。

**核心机制**
- 零魔法：use 开头 + 内部调用 Hook 的普通函数
- 每次调用在调用者 fiber 上创建独立 state 槽位，靠调用顺序定位
- 抽的是代码模板不是状态本身；共享状态靠 Context/状态库
- useFetch 式封装：请求生命周期/竞态/cleanup/依赖重发全打包

**最容易被追问的点**
- "两次调用 useCounter 共享 count 吗？" -> 不，同一 fiber 上两个槽位，调用顺序区分
- "为什么自定义 Hook 必须顶层调用？" -> 顺序错乱槽位对不上，数据串台
- "和 Vue composables 差在哪？" -> 同思想；Vue 靠依赖追踪无顺序限制，React 靠调用顺序
- "useDebounce 的灵魂是什么？" -> cleanup：value 连续变，旧定时器被连续掐死，只有最后一个活到 delay
- "纯计算函数该抽 use 吗？" -> 不，没有 Hook 调用就别加 use 前缀

**一句话类比**
自定义 Hook 像连锁加盟的配方手册：手册只有一份，但每家加盟店（调用处）按配方在自己店里（fiber 上）备独立的货（state）。
