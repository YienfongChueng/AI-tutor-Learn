# useEffect：副作用模型与依赖数组

**它解决什么问题**
渲染函数必须纯粹，但组件要发请求/开定时器/订阅事件--effect 给这些"渲染之外的事"一个统一的容器。

**核心机制**
- DOM 更新后跑 effect；挂载必跑一次
- deps 变化（Object.is 判等）-> 先跑旧 cleanup，再跑新 effect
- 卸载时跑最后一次 cleanup
- deps 是"重跑申请"：漏写 = 主动用旧快照
- cleanup = 撤销上一次副作用，保证世界只有一份生效

**最容易被追问的点**
- "deps 变一次跑几次？" -> 每次变都重跑：旧 cleanup → 新 effect，一条不落
- "[] 的 cleanup 什么时候跑？" -> 只有卸载时（deps 恒定永不重跑）
- "cleanup 打印的为什么是旧值？" -> 它是那一轮渲染闭包的快照（过期闭包）
- "ignore 旗标会不会被新一轮覆盖？" -> 不会，每轮 effect 独立闭包独立变量
- "React 为什么不能自动收集依赖？" -> 纯函数调用无拦截点，只能手动声明（vs Vue Proxy）

**一句话类比**
effect 是租房子：每换一次"钥匙"（deps 变）必须先退租上一间（cleanup）再签新一间，退房时把钥匙还的是**当初那间**（闭包快照）。
