# React 蒸馏：组件通信方式全景（vs emit/expose/v-model）

**它解决什么问题**
用一条通道（props）替代 Vue 的一堆通信专用语法。

**核心机制**
- 事件也是 props：`onXxx` 回调下传，子组件调用即上报
- 组件 v-model = 受控推广：value + onChange 手封
- 兄弟/跨级唯一路线：提升 -> Context -> 状态库，无 eventBus
- 草稿态是私有状态的合理例外，确认时才上报
- 判据：变更能否追溯到一次 setState

**最容易被追问的点**
- "emit 在 React 里对应什么？" -> 回调 props，机制同构只是注册形式不同
- "受控和提升是一回事吗？" -> 两个概念：受控=props驱动+回调上报；提升=状态上移到最近共同父级
- "草稿该放哪？" -> 子组件内部；提升它=每键重渲染整棵树+父级职责污染
- "`onAdd={addTodo(v)}` 错哪？" -> 渲染期立即调用，传给子的是返回值 undefined
- "子组件方法父组件想调？" -> 第一反应改成受控，而非暴露实例

**一句话类比**
Vue 给每个方向修了专用匝道，React 只留一条主干道（props）--所有车（数据、函数、JSX）都走它，方向感靠"谁传给谁"体现。
