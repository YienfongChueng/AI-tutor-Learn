# 4.12 项目收尾（README + 复盘表达）

**它解决什么问题**
做完了但讲不出来 = 没做完。把四个月的技术决策压成面试官爱听的"事故叙事"。

**核心机制**
- README 四段标准：功能 ≤5 行 / 选型说"为什么" / 运行方式新同事 5 分钟能跑 / 结构职责写"为什么存在"
- 复盘结构：场景 → 为什么这么选 → 踩过的坑 → 怎么解的
- 复盘是讲事故不是知识总结——坑是只有做过的人才知道的可信度细节
- 三条主线：queryKey 目录树与前缀失效 / 单一真相源（URL+派生）/ Context 广播与 localStorage 持久分工

**最容易被追问的点**
- "失效为什么失败？" → 把两个 key 并进数组 ≠ 前缀；失效参数是目录路径，两棵树各打一次
- "为什么 URL 存筛选？" → 可分享可刷新；state 是派生的不是第二真相源
- "token 为什么还要 Context？" → localStorage 不广播，logout 无组件感知；拦截器在 React 树外才读档案
- "复盘坑被追问细节怎么办？" → 只讲真实踩过的坑，泛化故事在"具体哪一行"露馅
- "新页面接入为什么零失效代码？" → 复用 lists() 前缀，mutation 失效自动波及

**一句话类比**
复盘像登山归来写攻略：重点不是"山顶风景好"（谁都知道），而是"哪段路有暗冰、怎么打的钉"——暗冰就是坑，钉就是解法，没登过顶的人写不出钉的位置。
