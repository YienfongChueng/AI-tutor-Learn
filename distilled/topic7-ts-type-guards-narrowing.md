# 类型守卫 & 类型收窄

**它解决什么问题**
联合类型收窄前只能访问公共成员，需要在运行时判断后让编译器收窄到精确子类型，才能安全访问特有成员。

**核心机制**
- 沿控制流用条件判断把宽类型收窄为子类型
- typeof 判原始类型；in 判对象有无某属性；instanceof 判类实例
- 相等性 / switch 收窄字面量联合；类型谓词 `x is T` 处理自定义判断
- 判别联合：同名字面量字段做判别符，用 `===` 收窄最稳
- default 分支赋 never 做穷尽检查，漏 case 即报错

**最容易被追问的点**
- "if(r.ok) 和 if(r.ok === true) 一样吗？" -> 对 `true|false` 布尔判别符等价；对字符串/数字字面量判别符，真值收窄无效，必须用 `===`/switch
- "typeof 能判 null 吗？" -> 不能，`typeof null === 'object'`，判 null 用 `=== null`
- "instanceof 能判 interface 吗？" -> 不能，运行时类型信息已擦除，只对 class 实例有效
- "Failure 加了 data 字段后 `'data' in r` 会怎样？" -> 两类型都有 data，in 失效，else 分支收窄成 never，`r.error` 编译报错
- "类型谓词 is 声明错了会怎样？" -> 编译器不报，运行时坑你，逻辑要自己保证

**一句话类比**
类型守卫像"安检口"：过一道检查就给你换个更精确的通行证（类型），没过的走另一条道（else 分支）。
