# 映射类型 & 索引签名

**它解决什么问题**
需要描述"任意键"的对象，或基于已有类型批量变换属性（变可选 / 只读 / 换值类型）时，用类型层面的"循环"生成新类型。

**核心机制**
- 索引签名 `[key: string]: T` 描述任意键对象，值类型须兼容所有显式属性
- `keyof T` 取出键的字面量联合（如 `'id' | 'name'`）
- 映射类型 `[K in keyof T]: ...` 遍历键生成新类型，`in` 是类型层遍历非运行时 in
- 修饰符 `+/-` 调整 `readonly`、`?`；`T[K]` 索引访问取值类型
- `Partial`/`Readonly`/`Record` 等内置工具类型底层就是映射类型

**最容易被追问的点**
- "索引签名和映射类型啥区别？" -> 索引签名键是任意 string（开放），映射类型键是 keyof 的固定集合（封闭）
- "interface {[key:string]:string; age:number} 为啥报错？" -> 索引签名值类型必须兼容所有显式属性，age 是 number 不兼容 string，改成 `string | number`
- "映射类型里的 in 和类型守卫 in 一样吗？" -> 不一样，映射类型 in 是遍历键，类型守卫 in 是运行时判断属性有无
- "-readonly 和 -? 干嘛的？" -> 移除只读 / 移除可选；加修饰符时 `+` 可省略

**一句话类比**
索引签名像"任意门牌的储物柜"（每个柜子装同一种东西）；映射类型像"照旧表抄新表"（键不变，按规则改每个格子的属性）。
