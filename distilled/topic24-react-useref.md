# 2.4 useRef：可变盒子与 DOM 引用

**它解决什么问题**
组件函数每轮重新执行，普通变量每轮归零；需要跨渲染存活但又不该触发重渲染的东西没处放，DOM 也需要一个 React 体系外的把手。

**核心机制**
- fiber 上存同一个 `{ current }` 盒子，每轮渲染原样归还
- 改 `.current` 不触发渲染：React 只对比 state/props
- 渲染发生时 `.current` 读活值（不引起 ≠ 读不到）
- DOM 引用：`ref={box}` 交给 React，commit 阶段自动塞入真实节点
- 卸载时 current 塞回 null

**最容易被追问的点**
- "另一个 state 变化引起重渲染时，ref 值会更新显示吗？" -> 会，渲染重新读活值；"永远显示旧值"的前提是没有任何重渲染
- "界面上要显示的数据能放 ref 吗？" -> 不能，改了不渲染甚至撒谎（暂停了还显示"运行中"）
- "快进视频/聚焦输入框用 state？" -> 不，直接拨 DOM 节点：videoRef.current.currentTime += 10
- "渲染期间能读写 .current 吗？" -> 不能，渲染应是 props/state 的纯函数
- "和 Vue 的 ref 什么关系？" -> 纯撞名；Vue ref 是响应式状态，React ref 是不响应的逃生舱

**一句话类比**
state 是对讲机（一喊全员集合重渲染），ref 是墙上的留言板（随便改，但没人会因此回头看一眼）。
