# 4.9 统计页（派生计算 + 分类汇总）

**它解决什么问题**
统计结果要不要存第二份 state？存了就是同步 bug 的温床——派生数据永远该是源的纯计算。

**核心机制**
- 统计永远是 records 的计算产物，不设第二个数据源
- 一次 useMemo 产出三数 + 分类汇总，deps 只写体内外部变量 [records]
- Map 按 category 分组累加，降序排序，key 用业务唯一字段
- mutation invalidate lists() 前缀自动波及统计页，零失效代码
- useMemo 只有两个正当用途：计算昂贵 / 引用稳定

**最容易被追问的点**
- "统计结果要不要 setStats？" → 永不，派生不存储，第二数据源必漂移
- "useMemo 必须包吗？" → 看两个用途：数据量小→用途1不成立；没有 deps 消费者/memo 组件→用途2不成立；都不占就可摘
- "为什么统计页不用写失效？" → 同一 lists() 前缀，mutation 失效自动覆盖
- "分类列表 key 用 index 还是 category？" → 会增删的列表用业务唯一字段，index 复用错位
- "派生计算放哪最合适？" → useMemo 单次产出对象，组件里只消费不搬运

**一句话类比**
统计像投影仪：胶片（records）换一帧，幕布画面自动跟着变——没有人需要"手动刷幕布"，也没有人会另存一份幕布截图。
