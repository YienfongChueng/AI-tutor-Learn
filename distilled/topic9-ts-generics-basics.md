# 3.1 泛型基础（函数/接口/类）

**它解决什么问题**
any 能复用逻辑但擦除类型关系，返回值变 any 编译器不再查错；泛型让一份逻辑保留「入参类型 -> 返回类型」的精确对应。

**核心机制**
- 声明 <T> 类型参数，调用时由实参锁定 T
- 同一次调用 T 是同一个类型，入参与返回共享它
- 三种载体同机制：泛型函数 / 泛型接口 / 泛型类
- 多数靠推断不必手写；可多参数 <T, U>
- 接口/类带 <T> 后字段类型随实例化而变

**最容易被追问的点**
- "T 和 any 差在哪？" -> any 擦除关系放弃检查；T 锁定后保留入参->返回对应且仍查错
- "对象字面量属性分隔用 ; 还是 , ？" -> 必须用 , ；接口/类型别名里 ; 和 , 都行，对象字面量（值）只能用 ,
- "何时要显式写 <number>？" -> 推断不够精确（字面量被推断成字面量）或想强制约束时
- "泛型类 new Stack<number>() 的 T 管多大范围？" -> 实例字段和方法都能用，整个实例锁定同一 T

**一句话类比**
泛型像带占位符的表单模板，交表时才填具体类型，复印成数字版/字符串版各有类型但模板只一份；any 像空白菜单，什么都能点但厨房不检查。
