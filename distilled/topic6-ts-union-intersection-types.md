# 联合类型 & 交叉类型

**它解决什么问题**
当一个值可能是多种形态之一，或需要把多个类型的能力拼到一起时，用类型运算精确描述其形态。

**核心机制**
- 用 `|` 表"或"：值是 A 或 B 之一，值集合为并集
- 联合收窄前只能访问公共成员，特有成员需先收窄（见 2.2 类型守卫）
- 用 `&` 表"与"：值同时具备 A 和 B，成员集合取并集
- 交叉同名属性类型取交集，冲突（如 `string & number`）坍缩为 `never`
- 字面量联合 `'a' | 'b'` 常替代枚举，收窄后可精确分支

**最容易被追问的点**
- "联合的成员是并集还是交集？" -> 值是并集，可访问成员是交集（与交叉正好相反）
- "联合 A|B 能直接访问 A 的特有方法吗？" -> 不能，只能访问公共成员，需先收窄
- "{id:string}&{id:number} 的 id 是什么？能赋值吗？" -> `never`，赋任何值都报错，因不存在既是 string 又是 number 的值
- "联合和交叉怎么记？" -> 联合做"选择"，交叉做"叠加"

**一句话类比**
联合像"任选其一的盲盒"（拆开前只敢用盒子共性）；交叉像"两份能力叠加在同一人身上"（全都会）。
