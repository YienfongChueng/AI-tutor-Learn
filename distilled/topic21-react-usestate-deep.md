# useState 深入：快照语义与批量更新

**它解决什么问题**
解释"点了三次计数器只加一"、"异步回调里拿到旧值"这类反直觉现象的根源。

**核心机制**
- 一次渲染 = 一次函数调用 = 一份闭包，state 在其中是 const 快照
- 一个事件内的所有 set 合并成一队，只渲染一次（React 18 自动批处理）
- 传值 = 成品（此刻算好），传函数 = 指令单（渲染时接力执行）
- 依赖旧值（计数/追加）必须传函数 `setX(x => x+1)`
- Object.is 判等，相同跳过渲染，所以更新必须换新引用

**最容易被追问的点**
- "连点三次 setCount(count+1) 为什么只加一？" -> 三条成品都是 0+1=1，互相覆盖
- "setTimeout 里读 state 弹旧值是 bug 吗？" -> 不是，闭包的本分；读最新值用 useRef
- "setObj({...obj}) 内容没变，会渲染吗？" -> 会，引用变了，Object.is 为 false
- "为什么不能 state.items.push(x)？" -> 原地改引用不变，Object.is 判等，React 不知道要更新

**一句话类比**
state 是定妆照：每轮拍摄定格一张，事件处理函数手里永远是自己的那张；set 是往剧组递单子（传值=成片，传函数=拍摄指令），一场戏拍完统一只补拍一轮。
