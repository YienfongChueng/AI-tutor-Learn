# State 与事件处理（useState 基础）

**它解决什么问题**
从"改数据它自己发现"（Vue）切换到"喊 setter 它替你改"（React）的心智模型。

**核心机制**
- useState 返回 [快照值, 触发器]，state 存 React 外部仓库
- 初始值参数只在首渲染生效，之后按调用顺序取回
- 事件回调连续 set：count 永远读本轮照片，不中途更新
- 引用判定：`Object.is` 比较新旧，原地改不触发渲染
- 不可变更新：数组 `[...arr,x]`/map/filter，对象 `{...obj,x}`

**最容易被追问的点**
- "连写两次 setCount(count+1) 结果？" -> 1。两次都基于旧照片算出 1；函数式更新 `c=>c+1` 才是 2
- "传值和传函数差在哪？" -> 传值=寄出瞬间定格的成品；传函数=寄指令单，React 处理队列时才执行且接流水线最新值
- "push 后 setList(list) 为什么没反应？" -> 引用没变，Object.is 判等，React 跳过渲染
- "onClick={add(n)} 为什么错？" -> 渲染期立即调用，返回值 undefined 被注册成处理器
- "更新丢失什么时候发生？" -> 多次 set 都基于同一张旧照片时，后一个成品覆盖前一个

**一句话类比**
Vue 数据像"带监控的仓库"（改了自动报警），React 数据像"没有监控的仓库"（你喊 setCount 才知道要盘点，且只认"换了个新箱子"不认"箱里偷偷换货"）。
