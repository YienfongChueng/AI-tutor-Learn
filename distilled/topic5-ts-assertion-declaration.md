# 类型断言 & 类型声明

**它解决什么问题**
TS 推断的类型和真实类型对不上（DOM、宽接口、无类型老库），需要你"告诉"TS 真相。

**核心机制**
- `as` 断言只改类型标注，不改运行时值，编译后消失
- 断言有约束：原类型与目标须有重叠，`as unknown as` 强制绕过（危险）
- 断言目标要选带目标属性的具体子类型（HTMLInputElement 而非 Element）
- `declare` 声明运行时已存在的东西，不产生任何 JS 代码
- `.d.ts` 给无类型模块/全局变量补类型，是 TS 与 JS 生态的桥

**最容易被追问的点**
- "断言会做类型转换吗？" -> 不会，只改类型标注，运行时值原样，调不存在的方法照样崩
- "断言成任意类型？" -> 直接断会报错，须 `as unknown as X` 强制绕过
- "断言目标随便选？" -> 不能，要选真正有目标属性的具体子类型；断言成父类型照样报错
- "declare 会产生代码吗？" -> 不会，纯编译时类型信息，编译后消失
- "对象里方法怎么写？" -> 方法简写 `m(x): T` 或属性式 `m: (x) => T`，不可混用

**一句话类比**
断言是"你向 TS 写保证书"（不改事实只改信任），declare 是"给已存在的熟人补张名片"（告诉 TS 这人长啥样，名片本身不是人）。
