# 4.9 统计页（派生计算 + 分类汇总）

## 讲解原文

### 核心理念：派生不存储

**统计结果永远是 `records` 的计算产物，不要存第二份。** 没有 `setStats`、没有 `stats state`——`records` 一变，统计就是重算一次表达式的事。存第二份数据源 = 制造同步 bug 的温床（与 4.7「URL 是唯一真相源」同一哲学）。

### 任务结构

- 路由：Layout 下加 `stats` 路由 + NavLink 导航入口
- `useRecords({})` 拉全量（统计要全貌，不带筛选）
- 一次 useMemo 产出：总收入/总支出/结余（reduce 累加）+ 支出分类汇总（Map 分组 + 降序）
- 埋考点：useMemo 的两个正当用途（2.6）：①计算昂贵 ②引用稳定（结果被 deps/memo 组件消费）

## 考核过程

### 口答题 1：为什么统计页不用写任何失效代码？

**用户回答**：因为这一页用的是 queryKey 的列表数据，如果数据不变，则这里统计的数据读取缓存的，如果数据变了，则依赖 records 数据重新计算。

**点评**：通过。同一个 `recordKeys.lists()` 前缀，mutation 的 invalidate 自动波及统计页的 key——前缀失效的再次正确应用。

### 口答题 2（追问两轮）：useMemo 必须包吗？

**首轮回答**：数据量少可以不包，如果数据量大，推荐包 useMemo。

**点评**：只答了用途 1（计算成本），引导补用途 2（引用稳定）的判断链：totalObj 的唯一消费者是 JSX 渲染（切导航只是引发重渲染，字符串插值只在乎值不在乎引用）→ 没有 deps 消费者、没有 memo 组件 → 用途 2 不成立 → **这里 useMemo 可以摘掉**，留着是"顺手"而非"必须"。二轮答出"没有 memo 组件，引用稳定在这里不存在，应该是不用包的"，通过。

### 代码审查（修 2 处）

- 🟡 `key={index}` → `key={item.category}`：分类列表会增删，index 作 key 复用错位（1.4 老坑回潮）；category 天然唯一且稳定
- 🟡 `.map()` 做副作用（map.set 累加但丢弃返回值）→ `.forEach`；顺带：`(item: RecordItem)` 冗余注解可删

### 做对的（一次通过项）

- 「派生不存储」落实：无第二份 state，一次 useMemo 产出全部统计
- reduce 累加收支、Map 分组（比对象分组稳，key 不怕原型链撞）、降序排序、结余推导
- `useMemo` deps 写 `[records]`——体内只读 records（2.6 考核时误写 deps 的问题未复发）
- 路由 + 导航 + tsc 0 错误
