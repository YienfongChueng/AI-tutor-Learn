# 条件与列表渲染（key 的真实作用）

## 讲解原文

### 一句话锚定

条件渲染五分钟就能学会，本节真正的主角是 **key：它不是"帮 diff 提速的优化项"，是元素的"身份证"——身份证变了，React 就把它当成另一个人（销毁重建，state 清零）；身份证没变，就是同一个人（复用更新，state 保留）**。

---

### 1. 条件渲染：JS 本身就是指令系统

```jsx
// v-if / v-else  ->  三元
{isLoggedIn ? <Dashboard/> : <Login/>}

// v-if（单分支） ->  && 短路
{hasError && <ErrorBanner msg={msg}/>}
```

**&& 的经典坑（Vue 人专属）**：

```jsx
{count && <Badge count={count}/>}
// count = 0 时渲染出什么？-- 一个裸的 "0" 字符串在页面上！
```

原因：`0 && x` 求值为 **0**（不是 false），而 React 会渲染数字 `0`。Vue 的 `v-if="count"` 自动按真值处理，从没让你踩过这个坑。修法：

```jsx
{count > 0 && <Badge count={count}/>}   {/* 让左边产出布尔值 */}
```

---

### 2. 列表渲染：map

```jsx
{todos.map(t => (
  <TodoItem key={t.id} todo={t} />
))}
```

规矩：**同级列表的 key 必须给、且兄弟间唯一稳定**。数据有 id 用 id，没有 id 说明数据该补 id（临时生成的随机 id 也比 index 强，只要它跟随数据本身而不是位置）。

---

### 3. key 的真实作用：diff 时的身份判定

React 拿到新旧两棵 element 树后**只做同层比较**。对同层的每个子节点，判定"是不是同一个"的依据是 `type + key`：

```
旧：[<li key="a"/>, <li key="b"/>, <li key="c"/>]
新：[<li key="z"/>, <li key="a"/>, <li key="b"/>, <li key="c"/>]   // 头部插入

React 按 key 配对：
  key="a/b/c" -> 同一个人：DOM 复用，只挪位置，组件 state 保留
  key="z"     -> 新面孔：创建新节点
```

没有 key（或全用 index）时，位置就是身份：

```
旧：[<li key=0/>, <li key=1/>]        // 数据 [A, B]
新：[<li key=0/>, <li key=1/>, <li key=2/>]  // 数据 [X, A, B]（头部插入）

按 index 配对结果：
  位置0: A -> X  "同一个人换了内容" -> 更新 props（还把 A 的 state 留给了 X！）
  位置1: B -> A  同上
  位置2: 新建 B
```

一次头部插入退化成**全员更新 + 一次新建**，性能损失是小事；真正的 bug 是：**组件的 state 跟着"位置"而不是跟着"数据"走**。

经典翻车现场（每个 TodoItem 里有个未受控的输入框草稿，用 useState 存）：

```jsx
{todos.map((t, i) => <TodoItem key={i} todo={t} />)}
// 在第 0 项的输入框里打了半截草稿，然后头部插入一条新 todo
// -> 你打的草稿"跑"到了别的 todo 上（它挂在位置 0 的 state 里）
```

Vue 的 `:key` 语义完全相同（你已经会），区别只有一个：Vue 的 diff 带编译期优化能更快定位变更，React 是纯运行时逐个配对——但"key = 身份"这个语义两边一模一样。

---

### 4. 反向应用：故意用 key 重置组件

既然"key 变 = 销毁重建 + state 清零"，它就成了官方的**重置开关**：

```jsx
<UserProfile key={userId} userId={userId} />
// 切换 userId 时，不用手动清空表单/内部 state，key 一换整个组件重新挂载
```

对照 Vue：你大概写过 `v-if` 先卸再挂或者 `:key` 强刷，同一个思路。

> ⚠️ 常见误解：**key 不是给"你"看的，也不是 performance 微调选项。** 它决定 state 的归属。用错 key 的症状往往不是"变慢"，而是"状态错乱、输入框串位、动画闪跳"这类诡异 bug。

---

### 5. 检查清单

| 场景 | key 该用什么 |
|------|-------------|
| 服务端数据列表 | 业务 id（稳定、唯一） |
| 静态配置列表（永不增删排序） | index 勉强可用 |
| 头部插入/排序/删除的动态列表 | **index 必出 bug** |
| 想强制重置组件 | 刻意切换 key（如 `${id}-${version}`） |
