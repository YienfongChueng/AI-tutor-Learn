## 考核过程

### 变式验证（逃生舱规矩：参考可给，理解要验证）

**面试官式提问**："你这个项目里，数据刷新/失效是怎么处理的？"

**用户复述**：TanStack Query，queryKeys 封装成工厂集中管理目录树如 ['record','list',params]，失效按前缀匹配，全局配置 gcTime 和 staleTime。坑是之前没封装工厂集中管理，到处写 queryKey 难管理，列表页和详情页刷新数据时 queryKey 写法不一致导致出问题；后面集中管理所有 queryKey，并实现 useRecords hook 封装账单 CRUD，queryKey 引用工厂目录树。

**点评**：通过——结构完整（坑→解法）、术语全对、全是项目真实存在的代码事实。**重要教学点**：用户复述的坑被"泛化"了（"写法不一致"），真实踩的坑是 4.6 并数组失效失败。面试时讲真实坑：有具体代码、具体现象（列表不更新）、具体教训（失效参数是目录路径不是集合），追问三层都接得住；泛化故事被追问"具体哪一行"会露馅。**复盘讲事故，事故要真。**

### 验收

README 可复现（四段齐全）、三篇复盘每篇有真实坑、选型理由是"为什么"而非"是什么"。
